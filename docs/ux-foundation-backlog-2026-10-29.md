## 1. 추진 목적과 기본 방향

데스크톱에서는 메모 작성과 자료 정리를 오래 이어가기 편하게 만들고, 모바일에서는 빠르게 기록하고 확인한 뒤 작업을 다시 이어갈 수 있게 한다. 색상과 컴포넌트는 공유하되, 화면 배치와 탐색 방식은 기기별 작업 목적에 맞춘다.

첫 구현 범위는 공통 레이아웃, 저장 신뢰성, 메모 작업 흐름이다. 이 범위에서 검증한 패턴을 할 일, 파일, 채팅에 적용한다. 전면 교체보다 기능별로 완료 가능한 단위로 출시한다.

## 2. 현황과 개선 우선순위

2026년 6월 제안서 이후 밝은 테마, 색상 토큰, 메모 목록과 미리보기 분할, 메모 자동저장, 채팅 시작 프롬프트 등이 구현되어 있다. 기존 기능을 새 개발 과제로 중복 등록하지 않고, 현재 동작의 완성도를 높인다.

아래 진단은 현재 소스 코드 기준이다. 레이아웃 충돌과 사용성에 관한 가설은 1단계에서 실제 렌더링과 기기로 확인한다.

| 과제 | 현재 구조와 영향 | 우선순위 |
| --- | --- | --- |
| 저장 중 입력 보호 | 메모 저장 응답으로 제목과 본문을 다시 대입한다. 요청 이후 입력한 내용이 덮일 가능성을 검증하고 차단해야 한다. | P0 |
| 조회 실패와 빈 데이터 구분 | 클립보드 조회 실패를 빈 값으로 처리하며, 할 일 조회 실패는 콘솔에만 기록한다. 실패를 정상적인 빈 화면이나 저장 완료로 오해할 수 있다. | P0 |
| 앱 높이와 고정 영역 통합 | 앱 본문, 페이지, 채팅이 하단 공간과 높이를 각각 계산한다. 키보드와 하단 탭을 포함한 공간 규칙이 필요하다. | P0 |
| 모바일 탐색 정리 | 하단 메뉴 6개와 작은 라벨이 고정 폭 안에 배치된다. 계정과 자주 쓰는 작업의 접근 경로를 재구성한다. | P1 |
| 반응형 기준 통합 | 전역 메뉴는 1024px, 채팅은 768px에서 전환한다. 중간 너비의 작업 공간을 검증한다. | P1 |
| 모바일 메모 편집 | 좁은 화면에서 편집과 미리보기가 세로로 쌓인다. 모드 전환으로 긴 이동을 줄인다. | P1 |
| 저장 상태와 작업 도구 통일 | 메모는 자동저장, 할 일은 수동저장이다. 상태 표현과 다음 행동을 일관되게 제공한다. | P1 |
| 공통 컴포넌트 동작 보완 | 공통 UI가 기존 컴포넌트를 감싸는 구조이며, 자체 모달에는 포커스 관리와 Escape 처리가 없다. | P1 |
| 반복 작업 효율 향상 | 검색, 필터, 목록 상태 복원, 단축키 등은 핵심 흐름이 안정된 뒤 적용한다. | P2 |

P0는 입력 손실과 핵심 작업 불가 문제, P1은 주요 흐름의 사용성, P2는 반복 사용 효율을 의미한다. 실제 장애가 확인되면 해당 과제의 우선순위를 올린다.

## 3. 개선 범위

### 포함 범위

- 데스크톱, 태블릿, 모바일의 앱 레이아웃과 내비게이션.
- 홈, 메모, 할 일, 파일, 채팅, 계정 접근 흐름.
- 로딩, 빈 데이터, 검색 결과 없음, 오류, 저장 상태, 재시도 동작.
- 공통 버튼, 입력, 헤더, 모달, 상태 안내와 접근성.
- 설치형 PWA의 키보드, 안전 영역, 연결 끊김, 업데이트 흐름.
- 핵심 시나리오의 회귀 검증과 단계별 출시.

### 후속 범위

- 완전한 오프라인 편집 및 자동 동기화.
- 기기 간 채팅 기록 동기화, 통합 검색 등 서버 설계가 필요한 기능.
- 네이티브 Android 앱 재작성과 기존 WebView 브리지 제거.
- 새로운 알림 시스템, 대규모 데이터 모델 변경.

오프라인 중 입력 보호가 필요하면 복구용 임시 초안을 검토한다. 도입 시 사용자별 격리, 만료, 로그아웃 시 정리 정책을 포함하며, 서버 저장 완료와 구분해 표시한다.

## 4. 기기별 목표 경험

| 구분 | 데스크톱 | 태블릿과 작은 창 | 모바일 |
| --- | --- | --- | --- |
| 주요 목적 | 작성, 비교, 정리, 관리 | 공간을 조절하며 작업 지속 | 빠른 기록, 조회, 재개 |
| 전역 이동 | 펼침과 축소가 가능한 사이드바 | 축소 메뉴 또는 하단 탭을 사용성 검증 후 선택 | 핵심 작업 하단 탭과 상단 프로필 |
| 메모 | 목록과 본문을 함께 보고 편집 | 목록을 접고 본문 확보 | 목록에서 상세로 이동하고 편집과 미리보기 전환 |
| 파일 | 폴더와 목록, 다중 선택 | 폴더 패널 접기 | 목록 중심과 명시적인 폴더 이동 메뉴 |
| 채팅 | 대화 목록 접기와 넓은 본문 | 보조 사이드바를 기본 접힘으로 검토 | 키보드 위 입력창과 대화 본문 유지 |
| 추가 작업 | 팝오버, 사이드 패널 | 작업 복잡도에 따라 선택 | 짧은 선택은 하단 시트, 긴 입력은 전체 화면 |

초기 설계 구간은 767px 이하, 768~1199px, 1200px 이상으로 잡는다. 최종 전환점은 실제 콘텐츠가 유지되는 최소 폭으로 결정하고, CSS와 JavaScript에서 같은 기준을 사용한다. 메모 편집과 채팅에서는 집중 모드를 검토하되 이전 화면으로 돌아가는 경로를 항상 제공한다.

## 5. 공통 설계와 구현 원칙

### 5.1 앱 레이아웃

앱 레이아웃에서 헤더, 내비게이션, 안전 영역, 본문 가용 높이를 관리한다. 각 페이지가 동일한 공간을 중복 예약하지 않도록 한다. 일반 화면은 문서 스크롤을 사용하고, 채팅처럼 높이가 제한된 화면은 본문 영역만 스크롤하도록 규칙을 구분한다.

키보드 열림, 가로 회전, 브라우저 주소창 변화, PWA standalone 실행에서 입력창과 마지막 콘텐츠가 가려지지 않아야 한다. 고정 안내는 제목과 주요 버튼을 지속적으로 가리지 않도록 배치한다.

### 5.2 상태와 저장

- 조회 상태는 불러오는 중, 데이터 있음, 데이터 없음, 실패로 구분한다.
- 편집 상태는 변경됨, 저장 중, 저장됨, 저장 실패로 구분한다.
- 저장 성공은 요청 당시 저장한 내용에만 적용하고, 이후 입력은 변경 상태로 유지한다.
- 저장 중 변경분은 다음 요청으로 이어지게 하며, 이전 응답이 최신 입력을 덮지 못하게 한다.
- 실패해도 입력과 선택 상태를 보존하고, 화면 안에 재시도 경로를 제공한다.
- 새로고침, 로그아웃, 화면 이탈, PWA 업데이트는 미저장 변경 및 진행 작업과 함께 검증한다.
- 삭제의 실행 취소는 복구를 지원하는 경우에 적용한다. 즉시 삭제만 가능한 기능은 대상이 명확한 확인 절차를 유지한다.

### 5.3 공통 UI와 접근성

공통 UI의 최종 사용 경로를 `src/shared/ui`로 정리한다. 동작을 검증하며 기존 래퍼를 점진적으로 교체하고, 한 번에 모든 컴포넌트를 다시 만들지 않는다.

우선 공통화할 대상은 페이지 헤더, 버튼, 아이콘 버튼, 입력, 검색·필터 도구, 빈 상태, 오류 상태, 모달, 저장 상태 표시다. Ant Design 컴포넌트와 자체 컴포넌트는 색상, 크기, 포커스, 비활성 상태 규칙을 공유한다.

모바일의 주요 터치 영역은 44×44 CSS px 이상을 목표로 한다. 아이콘 버튼에는 접근 가능한 이름을 제공한다. 모달에는 대화상자 의미, 제목 연결, 초기 포커스, 내부 포커스 유지, Escape 닫기, 종료 후 포커스 복귀를 구현한다. 색상 외에 텍스트나 형태로 상태를 전달하고, 동작 줄이기 환경과 200% 확대를 검증한다. 본문과 작은 텍스트는 두 테마에서 대비를 측정한다.

주요 사용자 문구는 한국어로 통일하고, 메모·할 일·파일·대화·계정 용어를 일관되게 사용한다.

## 6. 화면별 개선 작업

| 화면 | 구현 내용 | 완료 기준 |
| --- | --- | --- |
| 홈 | 클립보드 저장 상태와 조회 오류를 명확히 표시한다. 빠른 메모, 할 일 추가, 최근 작업 진입은 사용 빈도를 확인해 배치한다. | 조회 실패가 빈 값이나 저장 완료로 표시되지 않고, 주요 작업 시작 경로가 분명하다. |
| 메모 목록 | 데스크톱 목록과 본문 흐름을 연결한다. 모바일 목록과 상세 이동을 정리하고 검색·선택·스크롤을 복원한다. | 검색, 선택, 편집 후 복귀 과정에서 사용자가 이전 맥락을 찾을 수 있다. |
| 메모 편집 | 저장 중 입력 보호, 저장 실패 재시도, 모바일 편집·미리보기 전환, 이탈 처리를 개선한다. | 느린 응답과 실패 상황에서도 최신 입력이 유지되고 저장 여부를 식별할 수 있다. |
| 할 일 | 전체·진행 중·완료 필터, 완료 수, 분명한 저장 상태를 제공한다. 작업 편집과 그룹·우선순위 설정을 분리한다. | 추가와 완료 처리 후 저장 결과를 확인하고, 실패해도 변경분이 유지된다. |
| 파일 | 파일명 검색과 정렬, 모바일 폴더 이동, 업로드 상태, 공유 대상과 접근 권한 표시를 정리한다. | 드래그 없이 파일 이동이 가능하고, 업로드·공유 실패 시 재시도할 수 있다. |
| 채팅 | 대화 목록 접기, 최신 메시지 이동, 실패 후 재시도와 입력 보호를 개선한다. 한글 조합과 Enter 동작을 검증한다. | 키보드가 열린 상태에서도 입력·전송·최근 응답 확인이 가능하며 조합 중 오전송이 없다. |
| 계정과 설정 | 프로필 진입점에서 접근하도록 구성하고, 테마·친구 관리·로그아웃을 찾기 쉽게 정리한다. | 하단 탭에서 계정을 옮겨도 계정과 친구 관리에 접근할 수 있다. |

할 일 자동저장은 기존 API의 전체 목록 저장 방식과 요청 비용을 확인한 뒤 결정한다. 초기에는 수동저장을 유지해도 상태와 이탈 보호를 일관되게 제공한다. 파일 검색은 현재 조회 데이터 범위에서 시작하고, 서버 검색이 필요하면 별도 범위로 산정한다.

| 단계 | 기간 | 작업 | 산출물과 종료 조건 |
| --- | --- | --- | --- |
| 1 현황 측정과 설계 | 3~4일 | 실제 화면과 기기 점검, 핵심 작업 측정, 반응형 기준과 메뉴 구조 설계 | 개선 전 화면, 문제 목록, 작업별 기준 시간, 기기별 와이어프레임, 확정 백로그 |
| 2 공통 기반과 저장 신뢰성 | 1주 | 앱 높이와 고정 영역 정리, 내비게이션, 메모 저장 보호, 조회 오류, 공통 모달 보완 | 공통 레이아웃과 상태 규칙, 저장 경쟁 및 실패 검증 결과, 주요 가림 문제 해소 |
| 3 메모 흐름 구현 | 1주 | 데스크톱 목록·편집 연결, 모바일 모드 전환, 상태 복원 | 메모 생성·검색·수정·복귀 시나리오가 두 환경에서 통과 |
| 4 다른 화면에 확장 | 1~2주 | 할 일, 파일, 채팅, 홈, 계정에 공통 패턴 적용 | 기능별 핵심 시나리오 통과, 잔여 이슈의 우선순위 확정 |
| 5 실제 기기 QA와 출시 | 1주 | 접근성, 네트워크 실패, 인증, PWA, 회귀 검증과 단계적 적용 | 출시 체크리스트, 개선 전후 비교, 복구 절차, 잔여 과제 목록 |

구현 순서는 저장 상태 규칙과 공통 레이아웃을 먼저 확정하고, 메모에서 패턴을 검증한 뒤 다른 기능으로 확장한다. 각 단계에서 필요한 QA를 수행하며 마지막 주에는 전체 흐름과 교차 브라우저 검증에 집중한다.

## 8. 첫 구현 단위

첫 변경 묶음은 다음 범위로 제한한다.

1. 메모 저장 중 추가 입력, 실패, 화면 이탈에 대한 회귀 시나리오를 확보한다.
2. 저장 요청 당시 값과 현재 입력을 분리하고, 변경분의 후속 저장을 처리한다.
3. 클립보드와 할 일의 조회 오류를 화면에 노출하고 재시도를 제공한다.
4. 앱 레이아웃의 하단 여백과 채팅 가용 높이를 통일한다.
5. 모바일 하단 탭과 프로필 진입점을 재배치한다.
6. 메모 모바일 편집·미리보기 전환과 목록 복귀 상태를 구현한다.

완료 조건은 느린 네트워크에서도 입력이 유지되고, 모바일 키보드와 하단 메뉴가 작업을 가리지 않으며, 메모 작성부터 재조회까지 완료할 수 있는 것이다. 디자인 정리는 이 범위에 필요한 공통 요소부터 적용한다.

## 9. 검증 계획

### 9.1 핵심 시나리오

| 시나리오 | 검증 내용 |
| --- | --- |
| 메모 작성과 재조회 | 새 메모 입력, 자동저장, 목록 복귀, 다시 열기, 데스크톱과 모바일 간 서버 저장 내용 확인 |
| 저장 중 연속 입력 | 응답을 지연시킨 상태에서 계속 입력하고 최종 서버 내용과 화면 내용 비교 |
| 실패 후 복구 | 조회 실패와 저장 실패를 각각 발생시키고 입력 보존, 오류 구분, 재시도 확인 |
| 할 일 관리 | 추가, 완료 처리, 저장, 재접속 후 상태 확인 및 저장 실패 후 복구 |
| 파일 관리 | 업로드, 검색, 폴더 이동, 공유와 권한 회수, 다운로드, 실패 후 재시도 |
| 모바일 채팅 | 한글 입력, 줄바꿈과 전송, 키보드 열림, 긴 대화, 실패 후 재전송 |
| 설치형 PWA | 로그인 복귀, 재실행, 연결 끊김, 작성·업로드 중 업데이트 안내와 적용 |
| 키보드와 접근성 | 메뉴 이동, 모달 열기·닫기·포커스 복귀, 확대, 긴 제목과 파일명 표시 |

### 9.2 환경

- 뷰포트: 360, 390, 430, 768, 1024, 1280, 1440px. 전환점 바로 전후 너비도 확인한다.
- 데스크톱: Chrome과 Safari를 우선 검증한다.
- Android: Chrome 브라우저와 설치형 PWA, Samsung Internet을 검증한다.
- iOS: Safari를 검증하고, 홈 화면 설치 모드는 지원 범위에 포함할 경우 추가한다.
- 표시 조건: 밝은 테마, 어두운 테마, 200% 확대, 동작 줄이기, 긴 콘텐츠, 가로 회전.
- 데이터 조건: 빈 목록, 실제 사용량 수준의 목록, 긴 제목, 대용량 파일과 지연·실패 응답.

### 9.3 자동화

기존 단위 테스트와 lint, build를 유지한다. 메모 저장 경쟁과 상태 전이는 의미 있는 단위 테스트로 보호한다. 핵심 사용자 흐름과 대표 화면은 Playwright 등 브라우저 테스트로 검증하며, 정상·빈 데이터·오류 상태와 주요 반응형 구간을 우선한다. 키보드와 설치형 PWA 동작은 실제 기기 검증을 병행한다.

## 10. 성과 측정과 출시 기준

### 성과 지표

| 지표 | 측정 방식 | 초기 목표 |
| --- | --- | --- |
| 핵심 작업 완료 시간 | 동일한 데이터와 시나리오로 개선 전후 비교 | 대표 작업의 중앙값 20~30% 단축을 가설로 설정 |
| 작업 완료율 | 설명 없이 시나리오를 끝냈는지 관찰 | 반복 실패 구간 제거, 표본과 결과 함께 기록 |
| 저장 상태 이해 | 사용자가 저장 완료 여부를 정확히 판단하는지 확인 | 상태를 오해한 사례를 기록하고 재설계 |
| 입력 보존 | 저장 지연·실패·이탈 시나리오에서 비교 | 검증 시나리오 내 입력 손실 0건 |
| 레이아웃 안정성 | 기기별 가림·가로 넘침·스크롤 확인 | 주요 버튼과 입력창 접근 불가 0건 |
| 실제 기기 안정성 | 로그인·메모·파일·채팅·업데이트 반복 | 지원 환경의 핵심 시나리오 통과 |

기준값은 1단계에서 측정한다. 소수 사용자 검증은 문제 발견에 활용하고 통계적인 개선 효과로 일반화하지 않는다. 제품 담당자와 기존 사용자를 포함한 3~5명 검증을 우선 제안하며, 로그에는 메모 본문·클립보드·채팅·파일명 등 사용자 콘텐츠를 남기지 않는다.

### 출시 조건

- [ ] 입력 손실, 저장 완료 오표시, 주요 작업 접근 불가 문제를 해결했다.
- [ ] 데스크톱과 모바일의 핵심 시나리오를 실제 기기에서 통과했다.
- [ ] 조회 실패와 빈 데이터, 저장 실패를 구분하며 재시도할 수 있다.
- [ ] 로그인과 세션 복구, 업로드·다운로드의 기존 동작을 유지한다.
- [ ] 두 테마, 키보드, 모달 포커스, 주요 터치 영역을 확인했다.
- [ ] lint, 단위 테스트, build와 추가한 브라우저 회귀 검증을 통과했다.
- [ ] 작성 중 PWA 업데이트가 입력과 진행 중 작업을 잃게 하지 않는다.
- [ ] 출시 버전과 직전 배포 버전으로 복구하는 절차를 기록했다.

메모와 공통 레이아웃을 먼저 제한적으로 적용해 확인하고, 다른 화면으로 확대한다. 저장 문제나 인증·파일 기능 회귀가 확인되면 확대를 중단하고 직전 배포 버전으로 복구한다. 서비스 워커 업데이트와 캐시 전환까지 복구 검증에 포함한다.

## 11. 역할과 주요 위험

역할은 담당자 배정을 위한 제안이며, 실제 인원은 착수 시 확정한다.

| 역할 | 책임 |
| --- | --- |
| 제품 담당 | 주요 사용 흐름, 지원 환경, 범위와 우선순위 결정 |
| 디자인 담당 | 기기별 와이어프레임, 상태·컴포넌트 규칙, 사용성 검증 |
| 프런트엔드 담당 | 구현, 자동화, 접근성, 상태와 레이아웃 통합 |
| QA 담당 | 실제 기기 검증, 실패 재현, 회귀와 출시 체크리스트 |
| 백엔드·배포 지원 | 저장 API와 검색 범위 확인, 인증·파일 회귀 대응, 배포와 복구 |

| 위험 | 대응 |
| --- | --- |
| 전체 화면 재설계로 범위가 커짐 | 메모에서 검증한 패턴을 기능별로 확대하고 신규 서버 기능은 분리한다. |
| 공통 CSS 변경이 기존 화면에 영향 | 앱 레이아웃과 페이지의 공간 책임을 먼저 정하고 대표 화면을 회귀 검증한다. |
| 자동저장이 서버 요청과 충돌을 늘림 | 요청 순서와 후속 저장을 제어하고, 할 일 자동저장은 API 확인 후 결정한다. |
| 기기별 키보드와 PWA 차이 | 에뮬레이션 외에 Android·iOS 실제 기기에서 검증한다. |
| 기존 사용자의 메뉴 위치 혼란 | 주요 명칭과 목적지를 유지하고, 새 구조에서 접근 경로를 확인한다. |
| 테스트 계정과 데이터 준비 지연 | 첫 단계에서 계정, 샘플 데이터, 네트워크 실패 재현 방법을 확보한다. |

## 12. 착수 시 결정할 항목

1. 모바일 하단 탭을 5개로 유지할지, 실제 사용 빈도에 따라 4개로 줄일지 결정한다. 기본안은 홈·메모·할 일·파일·대화 5개와 상단 프로필이다.
2. 홈의 클립보드 중심 구성을 유지하면서 추가할 빠른 작업을 정한다.
3. 태블릿 내비게이션과 iOS 설치 모드의 지원 범위를 확정한다.
4. 할 일 수동저장 유지 여부와 임시 초안 도입 범위를 정한다.
5. 실제 담당자, 기기, 테스트 계정과 배포·복구 경로를 확정한다.

이 결정 전에도 저장 경쟁 재현과 보호, 조회 오류 표시, 현재 화면 측정은 시작할 수 있다.
