# Deepria Cloud 디자인 리뉴얼 실행 계획서

작성 및 최종 갱신: 2026년 10월 29일

상태: 후속 코드 구현과 브라우저 검증 완료, 실제 기기와 운영 검수 남음

대상: 데스크톱 웹, 모바일 웹, 설치형 PWA

## 1. 목표와 현재 기준

Deepria Cloud를 고유한 시각적 정체성과 편안한 작업 흐름을 갖춘 개인 작업 플랫폼으로 발전시킨다. 사용자는 설정에서 A 편집 디자인, B 그래픽 스튜디오, C 작업 콘솔을 선택하고 각 디자인의 라이트·다크를 독립적으로 사용할 수 있다.

후속 구현 기준은 `255379a`다. 메모·조회·업데이트 보호, 한글화, 모바일 편집 전환과 공통 모달을 구현하고 main에 병합·push했다. 최초 테마 구현은 `e6f5a91`, 직전 계획서 기준은 `e96295c`다. [후속 구현과 검증 결과](workspace-completion-2026-10-29/README.md)를 현재 근거로 사용한다. 운영 배포 완료와 실제 기기 검수는 구분해 확인한다.

이 계획서는 현재 구현과 남은 과업을 관리한다. 초기의 단일 디자인 선택 방식과 착수 후 7~8주 일정은 대체한다. 초기 디자인 탐색과 UX 진단은 관련 문서에 기록으로 남긴다.

## 3. 유지할 디자인 구조

| 디자인 | 제품에서의 성격 | 후속 검수 초점 |
| --- | --- | --- |
| A 편집 디자인 | 따뜻한 중성 바탕, 파란 강조, 큰 제목, 가벼운 목록과 추상 풍경 | 긴 한글 문서와 많은 목록의 정보 밀도 |
| B 그래픽 스튜디오 | 어두운 사이드바, 라임·바이올렛, 굵은 제목, 각진 면과 그래픽 | 긴 작업에서의 대비와 강조 비율 |
| C 작업 콘솔 | 정밀한 메타 정보, 제한된 곡률, 격자·궤도 그래픽 | 라이트·다크 모두에서 작은 글자와 장문 읽기 |

A를 기본 디자인으로 사용한다. 기존 밝기 선택이 있으면 유지하며, 선택이 없으면 라이트로 시작한다. C도 두 밝기를 모두 지원한다. 테마 선택은 현재 브라우저 기준이며 기기 간 동기화는 별도 범위다.

팔레트의 기준은 [themes.js](../src/features/appearance/lib/themes.js), 공통 구성 규칙의 기준은 [appearance.css](../src/app/styles/appearance.css)다. 초기 색상표와 시작 수치를 별도 사양으로 유지하지 않는다. 변경 시 실제 화면과 테스트를 함께 갱신한다.

## 5. 한글화의 범위와 원칙

실제 제품의 사용자 노출 문구를 한국어로 통일한다. 화면에 보이는 제목·설명·버튼 외에 placeholder, 동적 개수와 시간, 성공·실패 알림, 삭제 확인창, 툴팁, aria-label, 기본 대화 제목과 라이브러리의 기본 버튼도 포함한다. 홈과 사이드바의 장식 영문, B의 타이포그래피 그래픽, C의 콘솔 그래픽 역시 한글화 대상이다.

공식 제품명과 서비스명, 파일 확장자, 코드, 키보드 키 표기는 의미를 유지한다. 사용자 메모·파일명·폴더명·대화 내용과 API 경로·저장 키·내부 식별자는 번역 대상으로 삼지 않는다. 고정 폴더의 화면 이름과 내부 ID는 구분한다. 영어로 저장된 사용자 콘텐츠를 일괄 치환하지 않는다.

한글 문구를 적용할 때 각 테마의 글자 크기·줄바꿈·여백·버튼 폭을 함께 조정한다. 영어 길이에 맞춘 화면에 문구만 끼워 넣지 않고, B의 그래픽과 C의 고정폭 구성까지 실제 한글로 검수한다.

## 6. 남은 실행 순서

초기 후속 개발 작업량은 구현 완료에 따라 현행 일정에서 제외한다. 남은 작업은 다음과 같다.

| 순서 | 항목 | 현재 상태 | 종료 조건 |
| --- | --- | --- | --- |
| 1 | QA-02 배포 버전 확인 | 완료 | 운영의 255379a 및 dirty false, 한글 로그인과 비로그인 직접 진입 확인 |
| 2 | QA-01 실제 기기 검수 | 미실시 | Android Chrome·Samsung Internet·iOS Safari에서 설치·키보드·회전·인증·파일·대화 확인 |
| 3 | 보조기기와 표시 검수 | 미실시 | 스크린 리더, 브라우저 200% 확대, 실제 기기에서의 긴 문구와 터치 확인 |
| 4 | QA-02 복구 검증 | 절차 작성 | 배포 담당 환경에서 직전 버전 복구와 캐시 전환 확인 |

1번의 원격 상태는 읽기 전용으로 확인한다. 실제 계정 인증, 운영 데이터의 업로드·다운로드와 복구 실행은 담당 환경과 계정이 준비된 뒤 진행한다. 검증에서 발견된 문제는 영향에 따라 P0 또는 P1로 재등록한다.

## 8. 범위와 역할

프런트엔드는 UI, 테마, 문구, 상태와 접근성 구현을 담당한다. 디자인 검수는 한국어 조판과 6개 테마의 일관성을 확인한다. QA는 실제 기기·실패 시나리오·배포 결과를 확인한다. 백엔드·배포 지원은 실제 오류 코드와 메시지, 인증·파일 기능, 제공 버전과 복구 경로 확인에 참여한다. 담당자 배정은 별도로 확정한다.

다국어 전환 기능, 기기 간 테마 동기화, 완전한 오프라인 편집, 서버 통합 검색, 기기 간 채팅 동기화와 네이티브 앱 재작성은 별도 범위다. 한글화를 위해 기존 API 경로나 저장 스키마를 변경하지 않는다. 서버 영어 오류를 그대로 노출하는 경로는 프런트엔드의 한국어 사용자 안내와 기술 진단 정보를 구분하는 방식으로 다룬다.
