# Deepria Cloud 디자인 리뉴얼 계획서

작성일: 2026년 10월 29일  
상태: 디자인 방향 제안 및 실행 계획  
대상: 데스크톱 웹, 모바일 웹, 설치형 PWA  
예상 기간: 착수 후 7~8주

## 1. 목표와 추진 방식

Deepria Cloud를 고유한 인상을 가진 개인 작업 플랫폼으로 재설계한다. 첫 화면에서 브랜드의 성격이 느껴지고, 메모·파일·할 일·대화가 같은 제품의 일부로 보이며, 데스크톱과 모바일 모두에서 완성도 높은 화면을 제공하는 것이 목표다.

리뉴얼의 중심은 아트 디렉션, 타이포그래피, 공간 구성, 색상과 표면, 아이콘과 이미지, 인터랙션이다. 화면별 시각 디자인을 먼저 구체화하고 공통 디자인 시스템과 구현으로 연결한다. 기존에 정리한 저장·오류·내비게이션 개선은 디자인을 뒷받침하는 기반 작업으로 병행한다.

초기 산출물은 세 가지 시각 방향 비교와 홈·메모의 고해상도 시안이다. 구현 착수 전 실제 콘텐츠를 넣은 데스크톱·모바일 화면으로 디자인 수준을 평가한다.

## 2. 현재 디자인에서 바꿀 부분

현재 코드는 밝은 배경, 파란 강조색, 테두리와 둥근 카드, 작은 아이콘 버튼을 공통으로 사용한다. 일관성을 만들 기반은 있지만, 브랜드를 표현하는 요소와 화면별 구성 차이를 더 설계할 필요가 있다. 아래 항목은 코드에서 확인한 구조를 바탕으로 한 디자인 가설이며, 실제 화면 캡처와 함께 검토한다.

| 영역 | 현재 구성 | 리뉴얼 방향 |
| --- | --- | --- |
| 브랜드 | 데스크톱의 D 마크와 파란 강조색, 별도 PWA 꽃 아이콘 | 워드마크·심벌·앱 아이콘 사이의 시각적 관계를 정리하고 꽃 모티프의 계승 여부를 검토 |
| 타이포그래피 | Inter 중심 서체, 14px 본문, 30px 대표 제목 | 한글과 영문이 자연스러운 서체 조합, 제목·본문·보조 정보의 명확한 비례 |
| 화면 구성 | 페이지별 최대 폭과 상단 여백, 카드 패턴이 다름 | 같은 플랫폼의 리듬을 유지하면서 홈·문서·파일·대화에 맞는 구성 제공 |
| 표면 | 흰 카드, 테두리, 그림자를 여러 영역에 사용 | 배경·작업면·떠 있는 도구의 깊이를 구분하고 필요한 곳에만 경계 사용 |
| 홈 이미지 | 클립보드 아래 큰 정사각 갤러리 | 개인 이미지가 주는 분위기를 살리되 텍스트와 작업 영역의 비례를 함께 설계 |
| 아이콘 | Ant Design과 Font Awesome 의존성이 함께 존재 | 실제 사용처를 확인하고 선 굵기·크기·형태가 맞는 체계로 통일 |
| 모바일 | 데스크톱 요소를 접거나 세로로 배치 | 모바일 전용 제목 크기, 화면 밀도, 목록 구성, 탭과 시트 디자인 |
| 다크 테마 | 색상 토큰과 Ant Design 테마로 전환 | 독립적으로 표면·그림자·강조색·이미지 대비를 조정한 완성 화면 |

## 3. 디자인 방향 비교

세 방향은 탐색을 위한 제안이다. 같은 콘텐츠와 같은 화면 크기로 시안을 만들어 비교한다. 취향과 실제 사용 화면을 함께 평가한 뒤 한 방향으로 발전시킨다.

| 방향 | 시각적 성격 | 주요 표현 | 확인할 점 |
| --- | --- | --- | --- |
| A 편집 디자인 중심 작업 공간 | 차분함, 정교함, 개인적인 분위기 | 따뜻한 중성 배경, 잉크색 텍스트, 큰 제목, 섬세한 구분선, 절제된 블루, 사진과 텍스트의 비대칭 구성 | 한글 긴 문서와 많은 목록에서도 밀도가 적절한지 |
| B 그래픽 중심 디지털 스튜디오 | 선명함, 개성, 창작 도구의 활기 | 강한 포인트 색, 뚜렷한 제목, 기하학적 모티프, 크기 대비가 큰 영역 구성 | 장시간 사용과 정보가 많은 화면에서도 시각적 피로가 적은지 |
| C 어두운 작업 콘솔 | 몰입감, 밀도, 정밀함 | 깊이 있는 어두운 표면, 정밀한 정렬, 제한된 발광 효과, 가벼운 도구 영역 | 메모 읽기와 모바일 낮 환경에서도 가독성이 충분한지 |

우선 발전시킬 후보는 A다. 메모·파일·할 일·대화를 하나의 개인 작업 공간으로 연결하고, 홈의 이미지와도 자연스럽게 결합할 수 있다. 넓은 제목과 여백이 있는 홈에서 시작해 문서·목록에서는 밀도를 조절한다. 브랜드의 개성은 제목의 구성, 색상 배분, 심벌과 이미지 처리에서 만든다.

후보 A의 구체적인 첫 화면은 왼쪽의 절제된 브랜드 내비게이션, 상단의 날짜와 큰 제목, 넓은 클립보드 작업면, 옆의 이미지 영역, 하단의 최근 작업으로 구성한다. 이미지 영역은 개인 갤러리의 가치를 유지하면서 높이와 비중을 조절한다. 최근 작업은 기존 데이터로 제공 가능한 범위에서 설계한다.

## 4. 시각 디자인 시스템

아래 수치는 A 방향 탐색을 시작하기 위한 값이며 최종 사양은 고해상도 시안과 구현 화면에서 조정한다.

### 4.1 브랜드와 그래픽

- Deepria Cloud 워드마크와 작은 크기에서도 구분되는 심벌의 비례를 설계한다.
- 기존 꽃 아이콘을 브랜드에 통합할지, 앱 아이콘을 새 체계에 맞출지 시안을 비교한다.
- 로그인, 홈, 빈 화면, 앱 아이콘에 사용할 그래픽 언어를 정한다.
- 사용자 사진은 색상·크롭·프레임의 규칙으로 화면에 통합한다.
- 장식은 브랜드를 표현할 영역에 집중하고 문서와 긴 목록에서는 콘텐츠가 우선 보이게 한다.

### 4.2 색상과 표면

| 역할 | 밝은 테마 시작값 | 어두운 테마 시작값 |
| --- | --- | --- |
| 앱 배경 | #F5F4F0 | #151718 |
| 주요 작업면 | #FFFFFF | #1D2022 |
| 보조 영역 | #ECEDE8 | #25292B |
| 주요 텍스트 | #202625 | #F2F3EF |
| 보조 텍스트 | #5E6864 | #ADB6B0 |
| 브랜드 강조 | #355AE8 | #9CADFF |
| 경계 | #DDDFD8 | #373E3A |

색상은 브랜드 강조, 의미를 가진 상태, 사용자 콘텐츠로 역할을 나눈다. 주요 행동과 선택 상태가 드러나도록 강조색을 배분한다. 위험·성공·경고 색은 의미를 유지하며, 본문·버튼·아이콘·포커스별 대비를 실제 조합으로 측정한다. 시작값 자체를 접근성 검증 완료값으로 취급하지 않는다.

어두운 테마에서는 표면의 밝기 차와 얇은 경계로 깊이를 만든다. 그림자는 떠 있는 메뉴와 모달에 집중한다. 밝은 강조색 위의 글자색은 별도로 설계한다.

### 4.3 타이포그래피

- 한글 본문은 Pretendard 계열, 영문과 숫자는 조화로운 산세리프 조합을 첫 후보로 검토한다. 도입 시 배포 조건과 로딩 비용을 확인한다.
- 홈의 대표 제목은 데스크톱 40~48px, 모바일 28~34px 범위에서 탐색한다.
- 일반 화면 제목은 24~32px, 본문은 15~16px, 메모 읽기 본문은 16~18px를 시작값으로 삼는다.
- 보조 정보는 12~13px를 기준으로 하며 대비와 줄 간격으로 가독성을 확보한다.
- 제목, 본문, 날짜, 파일 크기, 코드에 각각 맞는 줄 높이와 숫자 정렬 규칙을 둔다.
- 한글 줄바꿈과 영문 긴 제목을 함께 확인하고, 글자 크기 축소보다 구성 변경을 우선 검토한다.

### 4.4 공간과 화면 비례

- 4px 단위 간격 체계를 사용하고 화면의 주요 구획에는 24·32·48px 간격을 구분해서 적용한다.
- 앱의 구조를 담당하는 영역, 실제 콘텐츠, 추가 도구의 위계를 분명히 한다.
- 홈은 큰 면과 작은 영역의 비례로 리듬을 만들고, 문서는 읽기 폭, 파일과 할 일은 정렬과 밀도를 우선한다.
- 모든 구획을 카드로 감싸지 않고 여백·배경 차·구분선·타이포그래피를 함께 사용한다.
- 곡률은 입력과 버튼, 작업면, 떠 있는 패널로 나누어 제한된 값으로 관리한다.
- 모바일에서는 제목과 주요 행동이 가까이 보이도록 상단 공간을 재구성한다.

### 4.5 아이콘과 모션

아이콘은 하나의 기본 계열을 정하고 기준 크기와 선 굵기, 버튼 안 배치를 통일한다. 파일 유형과 빈 화면 그래픽은 같은 색상과 형태 규칙을 사용한다.

버튼 반응은 120~160ms, 패널과 모드 전환은 180~240ms를 시작값으로 한다. 선택, 완료, 복사, 저장, 업로드에 맞는 피드백을 설계한다. 목록이 갑자기 이동하거나 글자가 흔들리는 효과는 피하고, 동작 줄이기 설정을 지원한다. 지속 애니메이션은 정보 전달이 필요한 경우에 한정한다.

## 5. 화면별 시각 리뉴얼

| 화면 | 새롭게 설계할 시각 구성 | 대표 산출물 |
| --- | --- | --- |
| 로그인 | 심벌과 워드마크, 인상적인 브랜드 영역, 단정한 인증 영역, 모바일 전용 비례 | 데스크톱·모바일 완성 시안 |
| 홈 | 날짜와 제목의 위계, 클립보드와 이미지의 비대칭 구성, 최근 작업의 가벼운 목록 | 브랜드를 대표하는 첫 화면 |
| 메모 목록 | 읽기 쉬운 목록 밀도, 정교한 선택 표시, 문서의 시작이 느껴지는 본문 영역 | 실제 메모 제목과 본문이 들어간 화면 |
| 메모 편집 | 문서 중심 작업면, 간결한 도구 영역, 제목·본문·코드·체크리스트의 조판 | 데스크톱 편집 화면과 모바일 모드 전환 |
| 할 일 | 강약이 있는 그룹 제목, 정렬된 행, 우선순위 표현, 절제된 완료 표시 | 데이터가 많은 상태와 필터 상태 |
| 파일 | 폴더 영역, 일관된 파일 썸네일과 유형 표현, 정렬된 메타 정보, 업로드 패널 | 목록·미리보기·공유 패널 |
| 채팅 | 문서처럼 읽히는 답변, 구별되는 사용자 메시지, 넓고 정돈된 입력면, 접히는 대화 목록 | 긴 답변과 코드가 있는 화면 |
| 계정 | 프로필과 설정 그룹의 명확한 위계, 친구 목록과 공유 관련 정보의 정돈 | 모바일 설정 화면 |

홈과 로그인은 브랜드의 개성을 가장 선명하게 표현하고, 메모·파일·채팅은 같은 시각 언어를 정보 밀도에 맞춰 조정한다. 실제 API에서 제공되지 않는 수치와 기능을 완성 시안에 표시할 경우 반드시 제안 기능으로 구분하고 구현 범위를 별도 결정한다.

## 6. 디자인 산출물과 검토 순서

### 6.1 첫 비교 산출물

A·B·C 각각에 대해 같은 데이터로 데스크톱 홈 1장과 모바일 홈 1장을 만든다. 총 6장의 시안과 색상·서체·표면·그래픽 샘플을 함께 비교한다. 분위기 참고 이미지와 실제 서비스 화면을 구분한다.

같은 화면 크기와 콘텐츠 양을 유지해 비교하고, 기능이 없는 홍보 화면에만 잘 맞는 디자인을 선택하지 않도록 한다.

### 6.2 선택 방향의 완성 시안

선택한 방향으로 다음 8개 대표 화면을 고해상도로 발전시킨다.

1. 데스크톱 홈 밝은 테마.
2. 모바일 홈 밝은 테마.
3. 데스크톱 메모 편집 밝은 테마.
4. 모바일 메모 편집 밝은 테마.
5. 데스크톱 홈 어두운 테마.
6. 모바일 홈 어두운 테마.
7. 데스크톱 메모 편집 어두운 테마.
8. 모바일 메모 편집 어두운 테마.

홈으로 브랜드와 구성의 힘을 보고, 메모로 실제 작업 화면의 완성도를 확인한다. 이후 파일·채팅·할 일·로그인·계정으로 확장한다. 각 화면에는 로딩, 빈 상태, 오류, 선택, 포커스와 긴 콘텐츠의 적용 규칙을 포함한다.

### 6.3 구현 가능한 프로토타입

대표 화면은 실제 브라우저에서 크기를 바꾸고 메뉴·패널·편집 전환을 확인할 수 있게 만든다. 초기에는 별도 디자인 프리뷰 경로에서 샘플 데이터를 사용해 비교할 수 있으며, 운영 사용자 데이터나 외부 배포는 필요하지 않다.

정적인 시안과 브라우저 구현의 차이는 같은 너비의 캡처로 확인한다. 글꼴 대체, 줄바꿈, 여백, 아이콘, 경계와 그림자를 조정한 뒤 공통 컴포넌트로 확장한다.

## 7. 일정과 작업 배분

프런트엔드 담당 1명과 디자인 담당의 지속적인 참여, QA 지원이 있는 경우 7~8주를 초안으로 잡는다. 한 사람이 디자인과 구현을 모두 수행하면 실제 작업량에 맞춰 재산정한다. 시안과 프로토타입 제작 범위가 확정되면 일정을 갱신한다.

| 단계 | 기간 | 핵심 작업 | 산출물과 종료 기준 |
| --- | --- | --- | --- |
| 1 시각 현황과 방향 탐색 | 1주 | 실제 화면 캡처, 브랜드 요소 정리, 세 방향의 홈 시안 제작 | 같은 조건의 시안 6장과 비교 결과 |
| 2 대표 화면 디자인 | 1주 | 선택 방향으로 홈·메모, 두 기기와 두 테마 구체화 | 대표 시안 8장, 서체·색상·공간 규칙, 후속 화면 구성 |
| 3 공통 디자인 구현 | 1~2주 | 브랜드 내비게이션, 타이포그래피, 표면, 도구, 패널 구현 | 브라우저 프로토타입, 토큰과 컴포넌트, 시안 대비 검수 |
| 4 전체 화면 리뉴얼 | 2주 | 메모·할 일·파일·채팅·로그인·계정 적용 | 실제 데이터가 있는 모든 주요 화면과 상태 |
| 5 시각 QA와 출시 | 2주 | 두 테마와 실제 기기 검수, 모션 조정, 사용성 및 회귀 검증 | 시각·기능 출시 기준 통과, 단계적 배포와 복구 준비 |

디자인 작업의 초기 배분은 브랜드와 방향 탐색 20%, 대표 화면과 디자인 시스템 30%, 전체 화면과 인터랙션 35%, 시각 QA 15%를 기준으로 한다. 개발 시간 배분과는 구분한다. 시각 QA 시간을 구현 지연의 보충 시간으로 소진하지 않도록 한다.

저장 손실 방지와 오류 표시 같은 P0 기반 작업은 초기 단계부터 진행할 수 있다. 화면 전반의 스타일 변경은 선택한 디자인 방향이 대표 화면으로 구체화된 뒤 시작한다.

## 8. 디자인 평가와 완료 기준

### 8.1 방향 선택 평가

아래 배점은 후보를 비교하기 위한 기준이다. 수치만으로 취향을 결정하지 않고, 각 점수에 화면에서 확인할 수 있는 근거를 붙인다.

| 항목 | 배점 | 확인 내용 |
| --- | --- | --- |
| 브랜드의 고유성 | 25 | 심벌·서체·구성·색상 조합이 하나의 성격을 만드는가 |
| 타이포그래피와 구성 | 25 | 시선의 시작과 순서가 분명하고 한글과 영문이 자연스러운가 |
| 화면 전반의 일관성 | 20 | 홈·문서·목록·대화가 같은 제품으로 느껴지는가 |
| 모바일 디자인 완성도 | 20 | 작은 화면에 맞게 비례와 구성을 다시 설계했는가 |
| 디테일과 움직임 | 10 | 아이콘·정렬·경계·상태·전환이 정교하게 연결되는가 |

후보와 현재 화면을 같은 데이터로 비교하고, 사용자가 느끼는 인상을 자유롭게 설명하도록 한다. ‘차분함·정교함·개인적인 분위기’ 같은 의도와 실제 반응이 일치하는지 확인한다. 시안 단계에서 소수 의견을 전체 사용자 선호로 일반화하지 않는다.

### 8.2 출시 전 시각 검수

- [ ] 브랜드 마크와 앱 아이콘의 관계를 결정하고 주요 진입 화면에 적용했다.
- [ ] 대표 시안의 핵심 비례와 타이포그래피가 실제 구현에 반영됐다.
- [ ] 모든 주요 화면에서 공통 서체·색상·간격·아이콘 규칙을 사용한다.
- [ ] Ant Design 기본 스타일과 자체 UI 사이에 의도하지 않은 스타일 차이가 없다.
- [ ] 360·390·430·768·1024·1280·1440px 및 전환점 전후를 검수했다.
- [ ] 한글과 영문 긴 제목, 많은 데이터, 코드와 표에서도 디자인이 유지된다.
- [ ] 두 테마의 텍스트·버튼·포커스·선택 상태 대비를 측정했다.
- [ ] 로딩·빈 상태·오류·업로드·저장 상태도 같은 디자인 언어를 사용한다.
- [ ] 실제 모바일 키보드와 설치형 PWA에서 화면의 비례와 접근성을 확인했다.
- [ ] 이미지와 폰트의 로딩이 주요 콘텐츠 표시를 방해하지 않는다.
- [ ] 모션과 동작 줄이기 환경을 검수했다.

### 8.3 기능과 성능 검수

기존 핵심 기능의 완료 시나리오, 저장 중 연속 입력, 네트워크 실패 후 복구, 인증, 파일 업로드·다운로드, 업데이트 중 작업 보호를 검증한다. 기존 lint·단위 테스트·build와 필요한 브라우저 회귀 검증을 통과해야 한다.

첫 단계에서 화면별 로딩과 상호작용 기준값을 기록하고 같은 환경에서 개선 후 비교한다. 이미지와 폰트는 크기·압축·로딩 전략을 정한다. 디자인 효과로 인해 성능이나 입력 반응이 악화되면 해당 효과를 조정한다.

## 9. UX 기반 작업과 관계

기존 계획의 상세 항목은 [UX 기반 개선 백로그](ux-foundation-backlog-2026-10-29.md)에 보존한다. 해당 문서의 초기 일정 대신 이 리뉴얼 일정에 맞춰 작업을 배치한다.

| 기반 작업 | 디자인 리뉴얼과의 연결 |
| --- | --- |
| 저장 경쟁과 입력 손실 방지 | 새 메모 편집 화면의 신뢰성 확보, 시각 설계와 별개로 우선 처리 |
| 조회 실패와 빈 데이터 구분 | 새 오류·빈 상태 컴포넌트와 함께 적용 |
| 앱 높이와 고정 영역 정리 | 모바일 내비게이션, 채팅, 집중 모드의 구조에 반영 |
| 검색·필터·상태 복원 | 각 화면의 도구 영역과 목록 디자인에 결합 |
| 모달 포커스와 접근성 | 새 패널·시트·모달의 공통 동작으로 구현 |
| PWA 업데이트 보호 | 전역 안내와 진행 중 작업 상태를 함께 설계 |

완전한 오프라인 편집, 서버 통합 검색, 기기 간 채팅 동기화, 네이티브 앱 재작성은 별도 범위로 유지한다. 디자인 시안에 필요한 실제 콘텐츠와 샘플 데이터를 준비하되 신규 서버 기능을 전제로 리뉴얼을 지연시키지 않는다.

## 10. 첫 착수 산출물

첫 단계의 완료물은 색상표나 기능 목록만으로 끝내지 않는다. 다음 자료를 하나의 비교 묶음으로 제공한다.

1. 현재 홈·메모·파일·채팅의 실제 화면과 시각 문제 표시.
2. A·B·C 방향별 데스크톱 홈과 모바일 홈, 총 6장.
3. 각 방향의 서체, 색상 비율, 표면, 아이콘, 그래픽 샘플.
4. 같은 데이터와 크기로 배치한 현재 화면 대비 비교.
5. 선택 방향을 발전시킬 홈·메모 8개 대표 화면의 제작 범위.

이 단계에서는 어떤 플랫폼으로 보이게 만들지 화면으로 판단한다. 선택한 방향을 바탕으로 대표 시안을 구체화한 뒤, 디자인 시스템과 전체 화면 구현으로 이어간다.
